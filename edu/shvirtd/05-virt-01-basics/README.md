## Задача 2. Выбор платформы виртуализации

**Вопрос:** выберите платформу для каждой задачи и объясните критерии выбора.

1) **Высоконагруженная MySQL, критичная к отказу**  
   - Выбор: виртуальные машины  
   - Критерии: отказоустойчивость (репликация/резерв), изоляция, предсказуемая производительность диска и сети, контроль состояния и backup.

2) **Разные web-приложения**  
   - Выбор: контейнеризация (Docker/Kubernetes при росте)  
   - Критерии: быстрый деплой, плотность размещения, масштабируемость, удобство доставки обновлений.

3) **Windows-системы для бухгалтерии**  
   - Выбор: виртуальные машины  
   - Критерии: совместимость с legacy/GUI-приложениями, управляемые лицензии, отделение рабочих сред пользователей.

4) **Высокопроизводительные расчёты на GPU**  
   - Выбор: ВМ/инстансы с выделенным GPU  
   - Критерии: высокая вычислительная производительность, доступ к ускорителям, единообразная среда для задач.

## Задача 3. Системы управления виртуализацией

**Вопрос:** для каждого сценария выбрать подходящую систему управления.

1) **100 VM Linux/Windows, общие задачи, требования к LB, репликации, backup**  
   - Выбор: `Proxmox VE`  
   - Обоснование: в этой задаче нужны централизованная виртуализация и удобное администрирование нескольких рабочих сред.

2) **Маленькая инфраструктура 20–30 серверов Linux/Windows, нужна бесплатная open source платформа с лучшей производительностью**  
   - Выбор: `Proxmox VE`  
   - Обоснование: бесплатная open source модель, зрелый KVM-стек и удобное управление.

3) **Максимально совместимое и производительное решение для Windows-инфраструктуры**  
   - Выбор: `Proxmox VE (KVM/QEMU)`  
   - Обоснование: предоставляет полноценную изоляцию и управление Windows-гостями в рамках бесплатной модели.

4) **Рабочее окружение для тестирования продукта на нескольких дистрибутивах Linux**  
   - Выбор: `Proxmox VE`  
   - Обоснование: быстрое разворачивание и изоляция разных сред с понятным администрированием.

## Задача 4. Гетерогенная среда

**Вопрос:** какие проблемы/недостатки и что делать для их снижения, и буду ли я её использовать?

### Проблемы и недостатки
- Разный инструментарий мониторинга и логирования между платформами.
- Рост сложности эксплуатации и повышения вероятности ошибки оператора.
- Неоднородные требования к лицензиям, обновлениям и безопасности.
- Сложнее управлять стоимостью и стандартизацией образов.

### Что нужно сделать для снижения рисков
- Ограничить число платформ по зонам ответственности и регламентировать их использование.
- Ввести единые шаблоны образов, сетевые политики, backup и patching.
- Свести наблюдаемость к единому стэку (метрики, логи, алерты, инвентаризация).
- Запустить процедуру регулярной проверки восстановляемости и доступа.

### Выбор: строить гетерогенную среду или нет?
- **Не создавал бы по умолчанию.** Для одного небольшого проекта/операционной модели целесообразнее унификация.
- Выбрал бы гетерогенную только при жёстких бизнес-ограничениях и при наличии процесса управления.
